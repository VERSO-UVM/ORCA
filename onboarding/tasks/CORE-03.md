## Why it matters

ORCA expects you to use AI tools to build, and to stay the person who owns every decision. The goal is not writing lots of prompts. It is judging what comes back: knowing how a solution must change to fit the project, debugging code that fails in ways you didn't write, and seeing why some output shouldn't ship even when it runs.

Some of you would rather build your core coding skills without AI, and that has a place too. Talk with your Pod lead about where on your project you can do that.

## The rules

**Use UVM's tools for project work.**

- Start with the tools UVM provides: Microsoft Copilot with your NetID, and Claude through UVM's license, which ORCA students can request as student employees (see AI-01).
- **Microsoft Copilot and GitHub Copilot are different tools.** Microsoft Copilot is the chat assistant you sign in to with your NetID, and UVM approves it. GitHub Copilot is the coding assistant inside GitHub and code editors, and it is **not** on UVM's approved list. Use GitHub Copilot only with public code and public data.
- Other tools without a UVM license, such as Cursor or a personal ChatGPT or Claude account, are also for **public data only**. Check UVM's [approved AI tools](https://www.uvm.edu/ai/supported-and-approved-ai-tools).
- **Never paste restricted or sensitive data into any AI tool, even a UVM-licensed one,** until you have checked its data level in CORE-04 and asked your Pod lead.
- No ORCA work will require a paid tool you buy yourself.

**Know what you commit.**

- You are responsible for every line you commit, whether you wrote it, copied it, or an AI wrote it.
- If you couldn't explain it or maintain it yourself, don't commit it. A good test: can you write a useful comment for it?
- In review, you must be able to explain every significant piece of code. If you can't explain it, it doesn't ship.

**Know when not to use it.**

- Don't use AI-generated code for sensitive data handling, security-critical paths, or anything where explainability is a legal or ethical requirement.
- If it takes several attempts to get the AI to do what you want, do it yourself. Coaching a tool can quickly cost more time than it saves.
- **Comments and documentation:** AI may draft them, but rewrite the draft until it says what your reader actually needs. Only you know the context, the reasons behind a choice, and who will read it.

**Where it helps most:** boilerplate and test data, repetitive tests (which you still review), and getting unstuck on a problem, as long as you understand the answer.
